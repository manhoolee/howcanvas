## 参数测试与菜单

实际供应商为 T8，不能直接照搬另一家供应商的字段。文生图和图生图都使用基础模型名，提交精确 `size`；不使用无法保证目标像素的 `resolution`。供应商依据 size 路由到对应规格，前端只暴露 Flare、Sunburst 两个入口。

菜单独立提供分辨率、长宽比、质量、自适应和自定义宽高。六档质量为 `auto`、`low`、`medium`、`high`、`xhigh`、`max`；请求成功不等于已量化各档视觉差异。

按用户要求停止 96 组全组合计划，复用已有成图，只补缺项，覆盖每个模型的分辨率和质量选项。预设像素输出、请求序列化、尺寸边界、透明背景和桌面/手机菜单已有验证记录。详见 [参数适配记录](GPT_IMAGE_25_COMPATIBILITY.md)。

## 生图交付诊断

原任务供应商记录：16:04:27 开始，16:05:14 成图；我方服务器直到 16:07:33 才收齐响应。抓取发现请求要求 `b64_json`，供应商成图后大响应体仍慢速传输，主要等待发生在此阶段。

针对同类请求的诊断样本中，URL JSON 仅数百字节；Base64 JSON 约数 MB，单次响应体传输额外消耗约 73 秒。该结果是诊断样本，不作为供应商平均性能承诺。

修复只针对 `ai.t8star.org` 的 Flare、Sunburst 后台任务，将响应格式转为 URL，保留提示词、参考图、蒙版、质量和尺寸。图片交付路径为：供应商图床原图 → 我方服务器下载并持久保存 → 前端从我方服务器下载、校验、缓存并显示。

用户随后发起的任务 `4ff19948-21ae-4d96-b784-c9500cd5d7b4` 验证如下：

| 环节 | 时间 |
| --- | --- |
| 服务器接收任务 | 16:24:29.291 |
| 供应商开始生成 | 16:24:30 |
| 供应商完成 | 16:25:19 |
| 我方收齐 URL JSON | 16:25:19.387 |
| 我方服务器保存原图 | 16:25:23.036 |
| 前端缓存完成 | 16:25:25.271 |
| 前端绘制回执 | 16:25:25.286 |

供应商生成约 49 秒，服务器接收到前端显示共 55.995 秒，供应商成图后约 6.3 秒交付，没有再次出现分钟级回包等待。详细证据见 [交付时序复查](IMAGE_DELIVERY_TIMING.md)。

## 长任务超时

虽然生产配置是 20 分钟，Node 内置 HTTP 客户端响应头和响应体等待仍有默认 300 秒限制。新增专用 Undici dispatcher 后，后台生图和普通 AI 代理均明确采用配置值。

当前生图单次上游请求允许 1200 秒，连接允许 60 秒；服务器取图在生成完成后独立允许 120 秒。前端后台任务等待没有 600 秒总截止，下载采用无进度限制和有限重试。供应商自身提前超时仍无法由我方延长。

超时修复于 16:40 上线，更新前没有运行或排队的图片任务。通过真实 HTTP 客户端与测试时钟验证：默认客户端在模拟 610 秒失败，修复后成功；1201 秒及取消仍会截止。组合回归 14 项通过，生产 Node 22 的超时专项 8 项通过；没有为此新增付费生图。
