## 4. 代码与功能工作

### 4.1 鉴权、模型和 Skill

- 服务端校验 Agent 文本模型是否存在且具备文本能力；失效配置会被清理，不再静默回退到错误渠道。
- 前端将服务端保存的 `channelId::model` 转换为服务器渠道选择格式，避免首轮请求命中本地空 Key 渠道。
- 服务器 AI 请求继续通过 `/api/ai/<channel-id>` 代理，真实 API Key 不下发浏览器。
- 增加视觉 Skill 允许列表、管理员配置、系统提示词、能力映射和 `skill({ name })` 工具入口。
- 服务器已用配置中的 DeepSeek 渠道执行 `/models` 和最小 Chat Completions 探测，均返回 HTTP 200；过程中未输出密钥。

### 4.2 文字输出和错误交付

- 兼容普通 JSON、Responses SSE、Chat Completions SSE 和 Codex 结构化事件。
- 合并仅包含增量片段的消息，处理 `item/updated`、工具调用、`turn.failed` 和初始化错误。
- 成功但没有文字时显示明确的“没有返回内容”，不再留下空白气泡。
- 生产 Nginx 对 `/api/ai/` 关闭缓冲和缓存，避免流式片段被网关延迟。

### 4.3 选区上下文和示意图标

- 选区摘要包含节点 ID、类型、标题、文本/提示词摘要和状态，并限制长度。
- 文本、图片、视频、音频、配置、组、插件节点均可展示；Blob、Data URL 和完整媒体内容不会写入对话历史。
- 服务器方案三和本地 Agent 请求都携带 `selectionContext` 与 `canvasSelection`。
- 输入框显示“已选 N 个画布元素”；发送后用户消息保留发送瞬间的选区快照，即使随后取消选择也不会串入其他节点。
- 图片、视频、音频、文本、配置和插件节点使用对应类型图标，超出显示数量提示，样式跟随浅色/深色画布主题。

### 4.4 npm 包边界

- 服务器方案三运行时没有对 `@basketikun/canvas-agent` 的引用，直接由主站前端和服务器 AI 代理完成。
- `@basketikun/canvas-agent`、`canvas-agent/` 和插件中的启动命令仍是本地 Codex/Claude 桥接功能，拥有独立版本和发布节奏。
- 因此 npm 包发布不是 v0.12.5 服务器上线的阻塞项；若以后维护本地桥接，再单独做版本和发布验收。

## 5. SSH 登录与生产部署

### 5.1 登录故障诊断

- 服务器：`114.132.45.243:2222`，部署目录：`/opt/infinite-canvas`。
- 今天 14:52 左右，日志显示 root 公钥登录已经成功，随后同一 IP 连续尝试 `ubuntu`、`debian`、`ec2-user`、`administrator` 等无效用户名。
- fail2ban 的 `sshd` jail 规则为 `maxretry=3`、`findtime=600`、`bantime=7200`，无效用户名尝试触发了封禁。
- 结论：该封禁不是 root 私钥错误，也不是 Canvas Agent API Key 错误。
