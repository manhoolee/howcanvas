# 工作台账号隔离与同步

生图工作台与视频创作台采用“服务器确认、账户本地缓存加速”的同步模型。服务器数据目录是账号归属的最终依据，浏览器 IndexedDB 只保存当前账号已被服务器确认的记录及待同步媒体。

## 数据边界

- 每个账号使用独立数据库：`infinite-canvas-user-<userId>`。
- 生图与视频记录分别位于 `image_generation_logs` 和 `video_generation_logs`。
- 媒体同步队列位于当前账号数据库的 `workbench_media_sync_queue`。
- 服务端记录位于 `server-data/workbench/<userId>/<kind>.json`，媒体位于对应账号的 `files/` 目录。
- 记录 ID 和媒体 `storageKey` 一旦归属于某账号，其他账号不能再次声明或上传。

## 同步流程

1. 登录或切换账号时递增认证 epoch，并立即清空上一账号的工作台界面。
2. 读取当前账号服务器记录，再与当前账号本地待同步记录按 ID 合并。
3. 如合并结果需要保存，先提交服务器；服务端丢弃已属于其他账号的记录 ID。
4. 前端再次读取服务器确认结果，并用该结果完整替换当前账号 IndexedDB 日志。
5. 只保留服务器确认记录引用的媒体任务；无归属任务从同步队列移除。
6. 媒体下载或补传在后台执行，不阻塞工作台记录列表。

该流程可自动修复历史版本留下的本地污染：例如服务器中 nanana 只有 3 条记录，而浏览器缓存含 27 条时，首次同步会由服务器确认的 3 条反向覆盖本地缓存。

## 服务端防线

- `PUT /api/workbench/:kind` 会扫描其他账号记录，拒绝重复归属的记录 ID，并返回 `droppedCrossAccount`。
- `PUT /api/workbench/:kind/files/:storageKey` 会拒绝上传已存在于其他账号目录的媒体键。
- 空列表或明显更短的客户端结果不会直接覆盖服务器已有历史，避免缓存恢复竞态导致误删。

## 开发约束

- 异步生成、轮询、媒体同步和日志保存必须携带启动时的 `ownerId` 与认证 epoch。
- 账号切换后，旧 epoch 的任务不得写入界面、日志库或服务器。
- 不要在账号切换时先渲染未经服务器确认的本地日志；服务器不可用时才将当前账号缓存作为离线回退。
- 新增工作台媒体类型时，需要同时更新允许的 `storageKey` 前缀、MIME 校验和跨账号测试。

## 回归检查

- admin 与 nanana 各自登录、刷新和反复切换时，只显示自己的记录。
- 在 nanana IndexedDB 人工放入 admin 记录后，重新进入工作台应恢复为 nanana 服务器记录。
- 以 nanana 身份提交 admin 记录 ID，响应中的 `droppedCrossAccount` 应增加，服务器不得保存该记录。
- 以 nanana 身份上传 admin 已有媒体键，应返回 HTTP 409。
- 切换账号前启动的生成任务完成后，不得覆盖新账号界面或写入新账号目录。
