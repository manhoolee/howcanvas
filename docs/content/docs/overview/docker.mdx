# Docker 部署

默认 Compose 从源码构建前端、后端和同源网关，并将账号、画布及媒体文件保存到 Docker 命名卷。需要 Docker Engine 24+ 和 Docker Compose v2。

## 启动

```bash
git clone https://github.com/manhoolee/howcanvas.git
cd howcanvas
cp .env.example .env
```

Windows PowerShell 使用：

```powershell
Copy-Item .env.example .env
```

首次启动前编辑 `.env`，至少替换以下两项：

- `AUTH_SECRET`：至少 32 个字符的随机值。
- `ADMIN_PASSWORD`：初始管理员密码。

然后验证配置并启动：

```bash
docker compose config
docker compose up -d --build
docker compose ps
```

访问 `http://localhost:3000`。以下健康检查必须返回 `{"ok":true}`：

```bash
curl http://localhost:3000/api/health
```

## 服务与数据

- `app`：Vite 前端的 Nginx 静态服务。
- `backend`：账号、画布、媒体、计费和 AI 代理服务。
- `gateway`：统一暴露端口 3000，并将 `/api` 同源转发到后端。
- `howcanvas_server-data`：后端持久化命名卷。

`docker compose down` 只停止并删除容器，不删除命名卷。`docker compose down -v` 会删除账号和业务数据，执行前必须备份。

## 公网部署

在端口 3000 前配置 HTTPS 反向代理，然后在 `.env` 中设置：

```dotenv
COOKIE_SECURE=true
```

如果前端与后端保持同源，`CORS_ORIGINS` 留空即可。修改 `.env` 后执行 `docker compose up -d` 重新创建受影响的服务。

## 统计分析（可选）

项目默认不启用统计。需要时可在 `.env` 中设置 `ANALYTICS_GA4_ID` 或 `ANALYTICS_BAIDU_ID`，留空即关闭。
