# Infinite Canvas 项目 Review

> 评审日期：2026-07-28  
> 评审范围：生图工作台、工作台媒体缓存、认证生命周期、画布图片节点工具条、线上部署状态

## 一、结论摘要

本轮核心问题集中在“渠道已生成结果，但客户端没有可靠接收、缓存和恢复图片”以及“工作台历史记录在刷新/切换账号期间不稳定”两条链路。当前已经完成前端恢复、服务器列表保护、本地缓存同步和图片下载兜底，线上前端已经重新构建部署。

目前项目可以继续使用，但工作台同步仍属于“列表合并 + 文件缓存”的渐进式协议，尚未具备完整的多端版本控制、删除墓碑和离线队列能力。若后续用户量或媒体量增加，建议优先升级同步协议和媒体任务队列。

## 二、当前系统链路

### 生图结果链路

```text
浏览器发起请求
    ↓
服务器 AI 代理 / 渠道
    ↓
渠道生成图片
    ↓
前端解析成功响应或非 2xx 响应体
    ↓
写入浏览器 image_files 缓存
    ↓
写入工作台记录
    ↓
上传工作台媒体文件到服务器
    ↓
服务器列表与本地列表再次合并
```

### 工作台打开链路

```text
读取本地记录和本地图片缓存
    ↓
立即显示本地历史列表
    ↓
读取服务器工作台列表
    ↓
按记录 ID 合并，较新版本优先
    ↓
最新记录优先下载缺失媒体
    ↓
媒体写入本地缓存后刷新页面图片 URL
```

### 认证切换链路

```text
登录 / 注册 / 退出推进 auth epoch
    ↓
请求携带发起时 epoch
    ↓
旧请求的 401 不得清理新会话
    ↓
当前会话失效才触发统一退出
```

## 三、已完成改动

### 1. 生图 API 结果恢复

- 支持从标准图片数组、图片 URL、Data URL、`b64_json` 等响应结构解析结果。
- 非 2xx 响应也先尝试解析响应体，覆盖“渠道已经生成，但代理状态码异常”的情况。
- 修正编辑请求中蒙版文件的构造方式。

### 2. 工作台记录同步

- 服务器列表和本地列表按 ID 做并集。
- 同一 ID 根据 `updatedAt` 或 `createdAt` 选择较新记录。
- 合并结果同时写回本地和服务器。
- 后端拒绝用空列表或较短列表覆盖已有的服务器历史。
- 账号切换时清理旧账号可见记录，防止跨账号混合。

### 3. 媒体缓存与下载

- 本地 `localForage` 保存工作台记录和图片 Blob。
- 打开工作台先显示记录，不等待全部图片下载。
- 服务器图片按最新记录优先补齐。
- 单个文件失败不会终止整轮同步；下载请求有 20 秒超时。
- 图片缓存完成后重新读取本地记录，重新生成当前页面可用的对象 URL。
- 下载按钮发现本地缺图时，会主动从服务器取回并写入缓存后再下载。

### 4. 任务状态流转

- 新任务发起时先创建“生成中”工作台记录。
- 生成完成后复用同一个记录 ID 更新为成功或失败。
- 生成图片先写入本地，再上传服务器，最后进行一次列表对齐。
- 使用串行保存队列，避免“生成中”记录和最终结果互相覆盖。

### 5. 画布图片工具条

- 图片节点工具条由单行改为上下两行。
- 工具顺序保持原有顺序，配置“更多”按钮放入第二行。
- 非图片节点不改变原有工具条布局。

## 五、风险与不足

### 高优先级：同步协议缺少删除语义

当前后端会保护较长的服务器列表，因此浏览器误读空列表不会删除历史。但这也意味着用户暂时不能安全地从一个端删除记录并让删除同步到其他端。

建议引入：

- `revision` 或单调递增版本号；
- 每条记录的 `updatedAt`；
- 删除墓碑 `deletedAt`；
- 服务端合并接口，而不是客户端提交完整列表覆盖。

### 高优先级：媒体同步仍是浏览器后台任务

页面关闭、浏览器休眠或网络中断时，媒体可能尚未完成下载/上传。当前有失败隔离和下次打开重试，但没有持久化的媒体任务队列。

建议增加：

- 待下载/待上传任务表；
- 重试次数和退避时间；
- 在线事件触发重试；
- 工作台显示“缓存中 / 已缓存 / 缓存失败”状态。

### 中优先级：对象 URL 生命周期

图片显示依赖浏览器对象 URL。对象 URL 不能跨刷新持久化，当前通过 Blob 缓存和重新读取恢复。后续可以封装统一的 `CachedMedia` 组件，集中处理加载、失败、重试和释放对象 URL。

### 中优先级：媒体下载与列表刷新耦合度仍较高

当前同步完成后会再次读取本地列表来刷新 UI；媒体量很大时，页面可能经历多次列表更新。后续可使用缓存事件或单条媒体完成回调，避免全量重新读取。

### 中优先级：生产部署安全

当前部署仍应持续关注 HTTPS、管理员密码轮换、`AUTH_SECRET` 管理、Cookie 安全属性和渠道密钥保护。敏感配置不应写入项目文档或版本库。

## 六、建议的后续迭代顺序

1. 将工作台列表保存接口升级为服务器端合并接口，加入版本号和删除墓碑。
2. 增加持久化媒体同步队列和“缓存状态”展示。
3. 封装统一图片/视频缓存组件，处理对象 URL、失败重试和下载。
4. 为工作台同步增加跨浏览器自动化回归：登录、打开工作台、刷新、切换账号、图片预览、图片下载。
5. 优化前端 chunk 拆分，降低首次打开工作台的加载时间。
