从提问升级到任务组织

面向谁 已经用过豆包、DeepSeek 等网页版对话工具，但还没有形成稳定工作方法的方案设计师。
教学目标

2工具判断知道哪些任务适合 Chatbox，哪些要文件助手、知识库、Agent 或 MCP。

从会问问题，到会组织任务
01

你已经在用的 AI 能力

豆包、DeepSeek、Kimi、ChatGPT 网页版，是大多数人的第一层 AI 使用经验。

先承认它有用示例：把一段入口广场说明改成甲方汇报语气。
再识别它的限制示例：网页版不知道哪份任务书是最新版本。
最后升级方法示例：把“帮我总结”改成“输出启动摘要表”。
本章示范线：同一段“入口广场说明”，先用 Chatbox 润色，再要求它转成“空间动作 / 汇报句 / 待确认”三列表。
从已有经验出发
Chatbox 适合什么

它很适合“轻量文本辅助”

豆包快速问答、中文表达、轻量创作
DeepSeek推理、结构化分析、代码类问题
Kimi长文阅读、资料摘要、文档问答
ChatGPT综合写作、多模态、工作流扩展
日常任务可以直接给的输入期望产出样例不适合期待
润色说明“这是我写的入口广场说明，请改成甲方汇报语气，120 字以内。”一段更清楚的 PPT 文案，保留原意，减少口语。不要让它替你确定设计策略。
会议摘要贴 8 条甲方反馈，要求按“功能 / 动线 / 立面 / 待确认”分类。一张反馈分类表，附需要项目负责人确认的问题。不要让它判断谁负责修改。
标题发散给项目定位和 3 个空间策略，要求生成 10 个汇报页标题。“界面激活”“慢行串联”“街角停留”等可筛选标题。不要把标题当最终概念。
输入示例“把下面 6 条评审意见整理成表格，列：原文 / 影响图纸 / 修改建议 / 待确认。”
输出示例生成评审意见任务表，方便项目组会逐项确认。
验收动作负责人只看是否漏项、是否误解原意，不让 AI 决定专业结论。
结论：网页版对话工具不是没用，而是它更适合处理“当前你给它的文字”。
从文本辅助开始
同一任务，不同输入

AI 的差异，很多时候来自你给任务的方式

只给一句话
帮我写一段商业街区方案说明。

常见结果：宏大、抽象、像模板；没有项目尺度、客群、动线、业态和空间落点。

给足可判断条件
项目是城市更新商业街区，面向周边社区和年轻消费人群。现阶段用于概念汇报，请写 120 字方案说明，必须包含：街区界面、慢行动线、公共节点、首层业态。不要写规范结论。

常见结果：更容易落到空间策略，也更容易被项目负责人修改。

差输入只给愿望，AI 只能猜你的项目、读者和判断标准。常见输出：漂亮但空。
好输入给任务背景、使用场景、必须包含项、不要做什么。常见输出：更像可改的初稿。
输入越像任务书，输出越像工作成果
为什么会失望

会聊天，不等于会工作

Chatbox 的常见限制
  • 每次都要重新讲背景
  • 看不到项目文件夹和历史案例库
  • 不知道哪份指标表是最新版
  • 不能自动整理整套项目资料
升级的方向
  • 给更准确的 Prompt
  • 管理上下文和资料输入
  • 连接知识库和工具
  • 用 Agent 执行多步骤任务
判断句：如果一个任务需要 AI 看多份资料、分步骤处理、输出文件并接受验收，它就已经不是普通聊天框任务。
具体例子：“把这段入口空间说明改顺”是 Chatbox 任务；“读取项目文件夹里 3 版任务书，找出成果范围差异并导出对比表”就是 Agent / 文件工具任务。
从聊天框到工作方法
Chatbox 工作卡

基础用户先练这 4 个动作，5 分钟内能见效

动作输入方式适合场景验收标准
改写贴一段原文 + 指定语气汇报说明、邮件、会议纪要意思没变，表达更清楚
摘要贴一段资料 + 指定字数和结构短会议记录、甲方反馈、评审意见关键信息没漏，能追溯原文
提问让 AI 先列“需要补充的信息”任务还不清楚、资料还不完整问题能带去问负责人或甲方
转表把散文改成表格字段案例、反馈意见、任务拆解每一行都能继续分工或检查
最小可用 Prompt：请把下面内容整理成表格，列为“原文要点 / 影响范围 / 需要确认的问题 / 建议下一步”。不要扩写，不要编造。
改写练习把“这个广场比较舒服，有人气”改成“入口广场通过树阵、台阶和首层开口形成停留界面”。
摘要练习把 12 条甲方意见压缩成“已确认 / 需补资料 / 影响方案”三组。
转表练习把一段案例介绍转为“项目类型 / 核心策略 / 可借鉴 / 不宜照搬”。
先练可验收的小动作，再升级到复杂工具
02

AI 做不到什么

先建立合理期待，后面学工具才不会幻想，也不会过早失望。

价值看交付物示例：20 页任务书变成启动摘要和问题清单。
失败看条件示例：没给场地条件，方案说明就会像模板。
边界看责任示例：消防、日照、指标只能列核查项。
本章示范线：把“AI 写得空”拆成缺目标、缺资料、缺工具、缺验收四类原因，再给修正 Prompt。
⏱ 5 分钟：把你今天的 3 件事分到绿 / 黄 / 红 / 灰。
能力与边界
金句 1 / AI 做不到什么
AI 写得很空，不要要求“再高级一点”。

改成可执行要求：补空间落点、删除无法证明的承诺、标出需要确认的信息。

节奏缓冲：边界章
价值

不要只说“提升效率”，要落到具体交付物

任务书启动摘要例：20 页任务书 → 范围、成果、节点、启动会问题。
案例对比表例：5 个商业街区案例 → 策略、来源、可借鉴、不宜照搬。
评审意见任务表例：一页评审截图 → 意见、影响图纸、建议动作、待确认。
PPT 页面文案例：确认后的策略表 → 页面标题、主张句、图注。
指标疑点清单例：两版指标表 → 冲突字段、来源版本、核查人。
项目归档说明例：成果文件夹 → 缺失文件、版本说明、后续维护建议。
示范：一份 20 页任务书 → AI 先生成“启动摘要表 + 启动会问题清单” → 人只验三件事：成果范围、时间节点、合同边界。
先定义交付物，再选择工具和 Prompt
做不来的原因

很多失败不是模型不聪明，而是任务条件不成立

缺什么表现方案工作中的例子
目标输出泛泛而谈只说“帮我写方案”，没有交付物、读者和使用场景
上下文内容像模板没给任务书、场地条件、甲方诉求、已有方案方向
工具只能给建议，不能执行网页版无法读取项目文件夹、整理多份资料、生成文件
权限查不到内部资料没有接入历史项目库、标准图集、部门模板和归档资料
验证错了也不容易发现案例无来源，指标无出处，专业判断没有人工确认点
1. 先问交付物我要的是摘要、表格、问题清单、PPT 文案，还是完整流程？
2. 再问资料够不够AI 需要看到哪些事实，才有资格回答这个问题？
3. 再问工具够不够只是聊天，还是需要读文件、查网页、整理表格、生成文件？
4. 最后问谁负责AI 可以标疑点，但规范、指标、消防、日照和结构判断要人工确认。
排查示范：“AI 写得很空”不要只要求“再高级一点”，改成“请输出空间策略表，列：设计动作 / 对应场地问题 / 需要确认资料”。
目标 + 上下文 + 工具 + 权限 + 验证
失败诊断样例

看到“AI 不行”时，先拆开排查

现场问题表面现象真正缺口修正动作
让 AI 写完整方案概念很空，像宣传语缺任务边界和场地事实先生成项目理解表和缺失资料清单
让 AI 做案例调研案例信息混乱缺统一字段和来源要求先规定字段，再要求来源和未确认标注
让 AI 判断指标回答很肯定但可能错专业责任边界错误只让 AI 列疑点，不让它下最终结论
让 AI 整理文件夹网页版只能给建议工具能力不够换 Agent / MCP，让工具能读文件
诊断演示原句：“帮我做商业街区案例调研。”修正：“请按项目名称、城市、类型、核心策略、来源、可借鉴、不宜照搬输出表格。”
诊断顺序：先看任务有没有说清，再看资料是否足够，再看工具是否能执行，最后看是否有人工验收。
现场用法：当同事说“AI 不行”时，不急着换模型，先问四句：你让它交付什么？你给了哪些事实？它需要读哪些文件？最后谁来验收？
不要把所有失败都归因于“模型不聪明”

03

怎么让 AI 听懂

Prompt 不是提问，是任务单；上下文不是越多越好，是要放对资料。

Prompt示例：让 AI 输出“范围 / 成果 / 节点 / 疑问”。
上下文示例：任务书包和案例资料包分开处理。
资料输入示例：先让 AI 复述任务书，再写 PPT 文案。
本章示范线：把“写商业街区方案说明”拆成角色、任务、背景、输入、输出、边界六个字段。
⏱ 5 分钟：选 1 件事，写出角色、任务、背景、输入、输出、边界。
把任务说清楚
开箱即用模板

标准 Prompt 模板：6 个字段

你是一名[角色]。 我要完成[任务]。 背景是[项目类型 / 阶段 / 读者]。 输入资料包括[资料范围 / 版本]。 请输出[表格 / 清单 / PPT 文案 / 设计说明]。 边界要求： 1. 区分事实、推断和建议。 2. 不要编造资料中没有的信息。 3. 标出需要人工确认的地方。
替换示例：任务书解读
角色建筑方案项目负责人。
任务整理项目启动摘要，不写正式方案。
输出范围 / 成果 / 节点 / 疑问 / 风险。
边界日期和成果项必须回到任务书原文核对。
5 分钟上手：选 1 件事，按 6 字段写一个标准 Prompt。
模板要能直接复制，而不是让听众回去再组装
Prompt

Prompt 是任务说明，不是咒语

角色让它按哪类专业视角处理：项目负责人、案例研究、汇报文案。
目标明确交付物：摘要、表格、问题清单、PPT 页面文案。
上下文给项目类型、阶段、读者、资料范围和已有判断。
格式规定字段、列名、长度、语气和是否区分事实与推断。
验收要求列来源、缺失资料、风险点和人工确认项。
模糊 Prompt
帮我分析这个商业项目。
可执行 Prompt
请基于任务书，输出商业项目启动摘要表：设计范围、成果要求、时间节点、甲方明确需求、需要确认的问题。区分事实和推断，不要编造。
输入资料例：任务书第 2-4 页，包含项目概况、设计范围、成果要求、时间节点。不要先给整本文件，也不要立刻要求写方案。
期望输出例：启动摘要表 + 5 个启动会问题，其中“效果图数量是否明确”标为待确认。输出能直接拿去开项目启动会。
验收动作例：负责人对照原文检查“7 月 18 日初稿”“内部决策会”是否来自任务书。日期、范围、成果项不能靠 AI 猜。
越复杂的设计任务，Prompt 越要准确
System Prompt

为什么系统提示词重要：它决定“默认怎么工作”

普通用户常见误解
  • 以为 Prompt 只是一次性的提问
  • 以为 AI 每次都会自动记住部门标准
  • 以为模型会自己知道哪些不能编造
  • 以为输出格式不重要，后面再整理也行

多轮对话

好的多轮对话，是把问题一步步收窄

低效对话
帮我写个方案。 不太对，再高级一点。 还是不对，再有设计感一点。 再短一点。 再正式一点。

问题：每一轮都在改感觉，没有补事实，也没有收敛标准。

高效对话
第 1 轮：先复述你理解的项目背景。 第 2 轮：列出还缺哪些信息。 第 3 轮：按“空间策略 / 功能组织 / 汇报表达”给 3 版方向。 第 4 轮：基于我选的方向，写 PPT 页面文案。 第 5 轮：自查事实、推断和风险点。

关键：每轮只推进一个动作，每轮都有输出标准。

轮次商业街区示范提问输出用途
第 1 轮请复述你理解的客群、场地和汇报对象。检查 AI 有没有读偏。
第 2 轮请列出还缺哪些设计判断，尤其是业态、动线、节点。形成提问清单。
第 3 轮基于已确认信息，给 3 个空间策略方向。供负责人筛选。
第 4 轮把选定方向转成“标题 / 主张句 / 图注 / 待确认项”。进入 PPT 页面制作。
多轮示例：同一段任务书不要一轮写终稿，先复述项目、再列缺失、再给 3 个方向，最后才生成汇报页文案。

验收

AI 输出能不能用，看这几项

事实准确

例：7 月 18 日初稿必须来自任务书原文。

来源可靠

例：案例图片要有链接、访问日期和授权状态。

专业边界

例：消防、日照、指标只列核查项，不下结论。

空间落点

例：“活力”要落到入口、界面、动线、节点。

风险提示

例：业态建议、运营强度要标“需甲方确认”。

可交付性

例：能继续进 PPT、任务表、归档清单。

实用标准：一段 AI 输出如果不能回到原资料核对、不能指出人工确认点、不能继续进入图纸或汇报页，就还不是可交付内容。

输出审稿法

拿到 AI 输出后，用 4 支笔检查

事实笔

项目名称、面积、城市、时间、任务范围是否与原文一致。

来源笔

案例、规范、数据、图片是否有来源，是否能回到原文。

边界笔

哪些是明确事实，哪些是推断，哪些必须负责人确认。

空间笔

概念是否落到功能、动线、界面、公共空间或运营场景。

基于社区型商业定位，方案优先组织首层连续界面与慢行入口节点，通过入口广场、街角灰空间和二层连廊提升停留与串联效率。业态组合和运营强度需在下一轮与甲方确认。

  • 有人工确认点

输出像模板目标和上下文不足例：补“社区型商业 / 概念汇报 / 甲方决策会”。
